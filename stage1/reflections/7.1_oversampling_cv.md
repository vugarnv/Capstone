My stage 1 set is Home Credit Default Risk on Kaggle, predicting whether a thin-file loan applicant repays, scored on ROC-AUC.

It is imbalanced. Defaults are the minority, only about 8 percent of applicants, so a model can score well on accuracy by just predicting "repays" for everyone and never flagging a default. That's exactly the case where imbalance handling matters.

Does that mean i should oversample during tuning? My honest answer is "maybe, and probably less than people assume". Because the metric is AUC, which is a ranking metric, oversampling mostly shifts the predicted probabilities rather than the ranking itself. It changes where I'd put the decision threshold, not how well the model separates the classes. So i'd treat it as one option to test, not a guaranteed gain, and i'd also try class_weight='balanced', which reweights the errors without inventing any new rows.

Where oversampling does help is forcing the model to take the minority class seriously instead of getting easy accuracy by always guessing "repays". In lending the costly mistake is the false negative, approving someone who then defaults, so pushing the model to learn the minority pattern is the point.

When do i apply it in cross-validation? Inside each fold, only on the training part, never before the split. SMOTE builds synthetic points by interpolating between a real point and its nearest neighbours. If i oversample first and then split, some of those synthetic points are blends of rows that end up in the validation fold, so the fold isn't unseen any more. Plain duplication is even worse, you get exact copies on both sides.

What goes wrong if i get that order wrong? The validation score looks great and means nothing. The model is being tested on near-copies of what it trained on, so it reports a number I can't trust, and it hides overfitting instead of revealing it. Then it falls apart on the real leaderboard.

Workflow:

Split off a final test set first and leave it shut.
Build a pipeline (imbalanced-learn) that chains preprocessing, then the sampler, then the classifier, so the sampler only ever sees training data.
Run stratified k-fold on the rest, keeping the original default ratio in each fold.
For each hyperparameter setting, the pipeline oversamples the training folds only and scores AUC on the untouched validation fold.
Pick the setting with the best mean validation AUC. Compare it honestly against a no-oversampling, class_weight run.
How do i check it generalises? Retrain the chosen setup on all the training data, then score the sealed test set once. If test AUC lands close to the cross-validation AUC, i can trust it. A big gap would mean I overfit.
