Which hyperparameters matter most, and why?

I'll answer from the models I actually understand so far, not ones the course hasn't taught me yet) For KNNthe key setting is k. A small k gives a jagged decision boundary that fits the training data too closely, low bias but high variance. A large k smooths the boundary and can underfit, high bias but low variance. So k sits right on the bias-variance trade-off, and i'd pick it on a validation set. The other setting that matters is the classification cut-off, the probability above which i call something positive. That decides how the model trades false negatives against false positives.

What trade-offs?

The cut-off is the main one. Lowering it catches more true defaulters but raises false alarms, raising it does the reverse. There's also accuracy versus honesty. If i try lots of settings and keep whatever scores best on one validation split, i end up tuning to that split rather than the real pattern, which is why cross-validation matters. And more complex models tend to be harder to explain, which is a real cost in lending, where a person may have to justify why an applicant was declined.

What knowledge, skills or data would i need?

Cross-validation to choose settings without fooling myself, a metric that matches the goal (AUC when classes are uneven, not raw accuracy), enough data to validate on, and domain knowledge to set the cut-off, since what counts as an acceptable miss is a business call, not a maths one.

How would I actuallyy apply this to my capstone?

My set is Home Credit Default Risk, predicting loan default, scored on AUC, with defaults the minority class. So the first thing i'd tune is the cut-off for the default class, chosen on a validation fold, and i'd compare a plain model against one with balanced class weights. I'd pick using cross-validated AUC and keep the test set sealed until the end. Once the course teaches the bigger models, the same habit carries over: change one setting at a time, judge it on validation, never on the test set.
